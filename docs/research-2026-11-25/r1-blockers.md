## 1. AdGuard (MV3 extension, tsurlfilter monorepo, GPL-3 except AGTree MIT)
Files: github.com/AdguardTeam/tsurlfilter/packages/{agtree,dnr-converter,tswebextension}.

1.1 Dynamic-rule rollback and limit reporting (CHECKED). tswebextension/src/lib/mv3/background/dynamic-rules-rollback.ts `withDynamicRulesRollback(snapshot, step, rollback, onRollbackError)`: take snapshot of dynamic rules, run the update, restore on failure and rethrow. limitations.ts `mergeLimitations` merges TooManyError counters so the UI can say how many rules were dropped. Effort: low (50 lines, own words). Idea only.
1.2 Converter design (CHECKED README of dnr-converter): one `FilterConverter`; rule "safety" helper `isSafeRule(rule)`; compact ruleset file format with source map so a matched DNR rule maps back to its filter line (used for filtering log); `$badfilter` applied across filters; `$removeparam` rules with identical conditions merged within one filter; `$csp` exceptions handled by a separate pass `convertCspRules()`. Not convertible (they are skipped with an error): `$replace`, `$jsonprune`, `$xmlprune`, `$hls`, `$popup`, `$redirect-rule`, `$referrerpolicy`. Supported with limits: `$redirect` (no allowlist), `$removeheader`, `$permissions`, `$cookie` (bare only), `$urltransform`, `$header` (no regex), `$to`, `$denyallow`, `$method`. A good checklist for what tools/filterlist.py should accept. Effort: medium to copy the behaviour; the code is GPL, so reimplement.
1.3 `$removeparam` in MV3 also covers in-page navigation (CHECKED services/remove-param-injection-service.ts + common/content-script/remove-param-main-world.ts `patchHistoryForRemoveParam`): DNR only sees real requests, so AdGuard injects a MAIN-world function via scripting.executeScript, patches history.pushState/replaceState, and re-injects on `webNavigation.onHistoryStateUpdated`. Fixes SPA URLs that never hit the network. Effort: low-medium. Idea only.
1.4 Stealth/Tracking protection in MV3 (CHECKED stealth-service.ts, KB page): DNR modifyHeaders rules (session/dynamic) for `DNT: 1`, `Sec-GPC: 1`, removal of `X-Client-Data`, `Referer` removal for search-engine referrers; `chrome.privacy.network.webRTCIPHandlingPolicy` set to `default_public_interface_only` (permission `privacy`); canvas fingerprint protection registered through `chrome.userScripts` in MAIN world at document_start, needs the user to enable "Allow user scripts" (Chrome 138+) and the script is renamed `//# sourceURL=<anonymous>` so stack traces do not reveal the extension. Self-destructing cookies are dropped in MV3 (KB, CHECKED). Effort: low for headers and WebRTC (modifyHeaders is "unsafe" but fine in the package).
1.5 Update model (CHECKED KB + beta post): built-in lists update only with extension releases; "Quick Fixes" filter loaded as dynamic rules for urgent fixes; custom filters by URL update on their own; over the dynamic limit, applied order is allowlist, user rules, custom filters (KB), 5,000 cap (not 30,000; reason UNKNOWN). Differential updates were "planned" (beta post, CHECKED); no evidence they shipped (UNKNOWN).
1.6 Scriptlet and cosmetic registration inside AdGuard MV3: UNKNOWN (not opened).

## 2. uBlock Origin Lite (GPL-3; platform/mv3 in gorhill/uBlock)
Already in section A: modes, scripting-manager, make-rulesets. New, from files opened now:
2.1 Strict block page (CHECKED make-rulesets.js `isStrictBlockRule`, `toStrictBlockRule`, `splitDnrRules`): every `block` rule that can hit main_frame is cloned into a `redirect` rule (priority 29) with `regexSubstitution: '/strictblock.html#\\0'` so the user sees a warning page with the blocked URL and a "proceed" option instead of a Chrome error page; the clone strips non-main_frame types. Runtime file extension/js/strictblock.js. Effort: low-medium. Idea only. (Ghostery does the same, see 4.2.)
2.2 Build-time rule merging (CHECKED src/js/static-dnr-filtering.js `mergeRules(rulesetMap, mergeTarget)`): hash each rule with the target array removed (keys sorted), then union the `requestDomains` / `initiatorDomains` arrays of rules with equal hash; a rule with no array (applies everywhere) wins and clears the array. This is how ~100k filters fit into far fewer DNR rules. Effort: low if tools/filterlist.py does not already do it (check). Idea only; algorithm is simple enough to write fresh.
2.3 Popup blocking without webRequest (CHECKED make-rulesets.js `processPopupRules`, `isPopupRule`; extension/js/prevent-popup.js): `$popup` filters are compiled to a hostname table plus regexes bucketed by a 7-char literal token, checked in `webNavigation.onCreatedNavigationTarget`; matching tab is closed. Effort: medium. Idea only. EasyList has many `$popup` lines that plain DNR cannot express.
2.4 Admin/no-filtering release (2026.907), de-duplicated scriptlet functions (2026.1012) and path-based scriptlet targets (2026.1122): CHECKED titles only; shows scriptlet code size and per-path targeting are live issues for uBOL.
2.5 New Chrome 145 `topDomains` / `excludedTopDomains` (CHECKED, Chrome API doc): a rule can match on the top-level frame's domain, in static rules too (the doc text about "session-scoped only" belongs to tabIds, not topDomains). Lets a static ruleset say "block X only on site Y" for third-party requests, or exempt a site, without initiator tricks. Effort: low, but only Chrome 145+; Edge parity UNKNOWN.

## 3. eyeo / Adblock Plus (webext-ad-filtering-solution, GPL-3, archived; monorepo not opened)
3.1 Diff updates on top of a bundled base (CHECKED gitlab issue 432, tags/release notes 1.9, 1.11): subscriptions with `diffUrl`; the diff is ALWAYS applied to the bundled base version of the list (1.11 fix: stop tracking "already applied" state); additions go to dynamic rules, removals of bundled rules use `declarativeNetRequest.updateStaticRules({disableRuleIds})` (needs Chrome 111+, they require 124); apply is all-or-nothing in design (issue 432) but 1.9.0 changed it to skip invalid filters and apply the rest; failures set status `synchronize_diff_error`. Chrome limit CHECKED in API doc: max 5,000 disabled static rules. Effort: medium. This is the best-evidenced answer to "update without store review": base in the package, small delta fetched as DATA. Diff file format: UNKNOWN (not published in pages opened).
3.2 Other lessons from release notes (CHECKED): main-frame DNR rules use `requestDomains` so `$document` works with `$domain` (1.11); regexes are validated with `isRegexSupported` during conversion because marking all valid caused add-rule errors later (1.9); dynamic rule state is persisted per subscription (1.15); snippets do not re-run on history events for speed (1.7); snippets injected via scripting API when page CSP blocks inline (1.12). Effort: low each.
3.3 Chrome blog says AdGuard and ABP supplied data that justified the 30,000 safe-rule limit and "98-99%" of AdGuard rules are safe (CHECKED in section A source). So both treat the safe/unsafe split as the main design axis.

## 4. Ghostery (extension GPL-3 / MPL headers; @ghostery/adblocker MPL-2.0)
Repo: github.com/ghostery/ghostery-extension, src/background/, scripts/.
4.1 Remote "fixes" ruleset plus per-rule disabling (CHECKED src/background/dnr.js, scripts/download-dnr-rulesets.js): rulesets `dnr-ads-v2`, `dnr-tracking-v2`, `dnr-annoyances-v2`, `dnr-fixes-v2`, `dnr-lang-<region>-v2` are downloaded at build time from their CDN and each has a `.metadata.json` mapping rule id to a preprocessor condition; at startup `disableExcludedRulesByPreprocessor(rulesetId)` calls `updateStaticRules({rulesetId, disableRuleIds})` for rules whose condition (e.g. `!#if` browser/feature flags) is not satisfied. Runtime fixes are fetched from their CDN and installed in a dynamic-rule id range (`FIXES_ID_RANGE`, `CUSTOM_FILTERS_ID_RANGE`, `REDIRECT_PROTECTION_ID_RANGE` in utils/dnr.js). Pattern worth copying: reserved id ranges per feature so one `getDynamicRules()` filter can replace one feature without touching others. Effort: low-medium.
4.2 Redirect protection (CHECKED redirect-protection.js, utils/dnr.js `getRedirectProtectionRules`): for every ad/tracking `block` rule that includes main_frame, a copy at priority+1 redirects to an extension warning page (`/pages/redirect-protection/index.html?url=<base64>`); per-hostname allow rules (priority above) for user exceptions; if disabled, one max-priority `allow` on `*` main_frame. Tab's last URL kept in an AutoSyncingMap with 5 min TTL so the page can offer "continue". Same idea as uBOL strict block (2.1). Effort: low-medium.
4.3 Never-Consent (CHECKED never-consent/autoconsent.js, gpc.js): uses DDG autoconsent `filterCompactRules(compactRules, {url, mainFrame})` to send each frame only the rules that match its URL; config `heuristicMode` 'reject' (only click reject buttons) or 'tier2' (also acknowledge/accept) for banners no rule covers; `enablePopupMutationObserver: true`; `enableHeuristicHitTest` behind a remote feature flag because it caused false matches (autoconsent issue 2543); per-domain remote action `ACTION_DISABLE_AUTOCONSENT` fed by their public broken-page-reports repo. Effort: low if your vendored autoconsent version has these options (UNKNOWN, check version).
4.4 GPC (CHECKED gpc.js): DNR header rule `Sec-GPC: 1` (dynamic, range `GPC_RULE_ID`) plus a content script registered with `registerContentScripts({persistAcrossSessions:true})` in MAIN at document_start that defines `navigator.globalPrivacyControl` (spec requires both); unregistered when disabled; domains where it broke come from remote config. Effort: low.
4.5 Other: Google SERP rule `pws=0` via `addOrReplaceParams` on google.*/search (CHECKED build script; disables personalised search, regexFilter, main_frame); element picker, YouTube ad notice requiring userScripts (youtube.js), WhoTracks.me stats/bloom filter (scripts/download-wtm-*.js). Tracker database is CC BY-NC-SA: do not copy.
4.6 @ghostery/adblocker (MPL-2.0, github.com/ghostery/adblocker, 1.0k stars): FiltersEngine with binary serialisation, packages adblocker-webextension-cosmetics (content-script side) and adblocker-extended-selectors (procedural selectors). Could replace hand-written procedural cosmetics; runs in JS so needs hostname-indexed lookups per frame. Effort: medium-high (dependency, bundle size UNKNOWN). Ghostery itself still uses an engine for cosmetics under MV3 (REPORTED in section A).

## 5. Brave (MPL-2.0 core and lists)
5.1 Debouncing (CHECKED wiki Debouncing, brave-core components/debounce/core/browser/debounce_rule.h, brave/adblock-lists brave-lists/debounce.json): bounce-tracking redirects are turned into browser-internal redirects. Rule fields: include/exclude URL patterns, `action`, `param`, optional `prepend_scheme`, optional `pref`. Actions: `redirect` (target in a query param; 33 rules), `base64,redirect` (4), `regex-path` (10), `regex-path-template` (1) (counts of the file today, 48 entries, CHECKED). Includes affiliate and email-click trackers (skimresources, redirectingat, mailchimp, tradedoubler, reddit mail, pstmrk) and AMP: `cdn.ampproject.org/c/s/(.*)` and turbopages, gated by a pref.
   MV3 mapping (INFERRED): `regex-path` entries map straight to DNR `redirect.regexSubstitution` with a `regexFilter` capture group (Chrome allows `\1`; DDG proves it ships, see 6.1). Query-param entries are harder: regexSubstitution does not URL-decode, so the target comes out still encoded. Use `webNavigation.onBeforeNavigate` plus `tabs.update` (needs the same host access you already have) and decode in JS. Start with the regex-path ones and a short query-param list. Effort: low-medium. Data reusable under MPL-2.0 (keep file notice).
5.2 Tracking-param lists (CHECKED): query-filter.json (4 groups of params, first group `*://*/*` with ~50 names e.g. `__hsfp`, `_gl`, `igshid`-style ids, `msclkid`, `mc_eid`, `oly_*`, `sfmc_*`) and clean-urls.json (51 per-site groups: facebook `__tn__`, `__cft__[0]`, amazon per-TLD, etc.) used for "copy clean link" and param stripping. Merge with your rules/removeparam.json after review; per-site scoping maps to `requestDomains`. Effort: low. MPL data.
5.3 Farbling (CHECKED wiki Fingerprinting-Protections, thin): randomise API outputs with a seed per session and per eTLD+1 (third-party frames use the top-level seed); block other APIs by returning plausible empty values. API list and strict/standard levels not on that page (UNKNOWN). Implementation in brave-core is renderer C++ (not extension-portable). For an extension use DDG's Apache-2.0 content-scope-scripts instead (6.3). 
5.4 adblock-rust (CHECKED README, CHANGELOG): native engine, not DNR-bound; uses uBO-compatible resources; 0.13.6 (2026-11-17) added `$to`; DAT format v7; flatbuffer data format. WASM/JS bindings exist (`adblock-rs` on npm) but a native-style engine in a service worker is not how MV3 blockers work; not worth it for AdBrake. Brave "forgetful"/ephemeral storage, bounce-tracking storage clearing are browser-level: no extension equivalent (INFERRED).

## 6. DuckDuckGo extension (Apache-2.0; best licence for reuse)
Repo: github.com/duckduckgo/duckduckgo-privacy-extension, shared/js/background/*, packages/ddg2dnr/lib/*.
6.1 ddg2dnr is a ready MV3 generator (CHECKED lib list): tds.js, ampProtection.js, trackingParams.js, gpc.js, smarterEncryption.js, cookies.js, trackerAllowlist.js, temporaryAllowlist.js, rulePriorities.js, requestBlocklist.js, combined.js.
   - AMP: `generateAmpProtectionRules` makes one `redirect` rule per config regex with `regexSubstitution: 'https://\\1'`, `resourceTypes:['main_frame']`, priority 40000, `excludedInitiatorDomains` and `excludedRequestDomains` from config exceptions, validated with `isRegexSupported({regex, requireCapturing:true})`. Note: they replace `\S` with `.` because `\S` misbehaved in Chrome (their comment). Formats: `google.*/amp/s/(...)` and `*ampproject.org/*/s/(...)` (CHECKED amp-links.json).
   - Tracking params: ONE redirect rule with `queryTransform.removeParams` of the config list, wildcard/regex params dropped (comment: "can't support these in MV3"), `excludedRequestDomains` for exceptions, main_frame only.
   - Priorities: tracker rules start at 10000, +100 per more specific subdomain level, +1 step for ordered rules, ceiling 19999, regex capped at 900 of 1000 (CHECKED tds.js constants). Good template for deterministic priorities.
   Effort: low-medium; copy with attribution.
6.2 Runtime generation with consistency check (CHECKED dnr-config-rulesets.js, dnr-gpc.js, dnr-smarter-encryption.js): they fetch remote config (data), generate rules in the service worker, install as dynamic rules, and store an "etag rule" (a dummy `allow` with `requestDomains:['etag.invalid']` and urlFilter = etag) in the same id range so rule state and config state can never disagree after a crash; GPC header as a SESSION rule; Smarter Encryption (HTTPS upgrade) keeps `upgradeScheme` and allow lists as session rules updated per domain. Per-feature `exceptions` carry a `reason` URL (privacy-configuration repo, licence NOASSERTION: do not copy data). Effort: low. Strong pattern for your updater.js.
6.3 Fingerprint and embed protection in page world (CHECKED feature file list of content-scope-scripts/injected/src/features, Apache-2.0): fingerprinting-canvas, -audio, -hardware, -screen-size, -battery, -temporary-storage, gpc, referrer, click-to-load, cookie, web-compat, tracker-protection, element-hiding. click-to-load replaces social embeds with a placeholder and only allows the request after a click. Not read in depth (UNKNOWN: breakage rate). Effort: medium-high; test burden large. Reported breakage: DDG keeps per-site exceptions in remote config (CHECKED config shape).
6.4 Surrogates (CHECKED tracker-surrogates/surrogates): ad_status.js, adsbygoogle.js, amzn_ads.js, amzn_apstag.js, analytics.js, api.js, beacon.js, chartbeat.js, criteo.js, fb-sdk-new.js, ga.js, google-ima.js, gpt.js, gtm.js, inpage_linkid.js, nielsen.js, noop.js, outbrain.js, youtube-iframe-api.js. Apache-2.0 overall. This covers most of section A.2's wish list with ready, maintained code (see licence caveat for embedded third-party snippets). Effort: low. Highest return per hour in this report.
6.5 Link protection beyond AMP (CHECKED amp-protection.js): non-Chromium "deep extraction" fetches the AMP page and reads canonical URL (Firefox only; Chromium skips it), so Chromium relies on URL regexes only.

## 8. Ranked top ideas for AdBrake (value, effort, licence)
1. DDG tracker-surrogates as redirect stubs: low effort, Apache-2.0.
2. Debounce + AMP de-redirect via DNR regexSubstitution (Brave debounce.json data MPL; ddg2dnr ampProtection Apache): low-medium.
3. Update channel = bundled base + `updateStaticRules` disable list + small dynamic "fixes" range + etag rule + rollback (eyeo, Ghostery, DDG, AdGuard): medium; ideas only except DDG Apache code.
4. Strict-block / redirect-protection warning page (uBOL, Ghostery): low-medium; ideas only.
5. Tracking-param lists from Brave (MPL) and DDG (Apache), exceptions with reasons, plus SPA history patch (AdGuard idea): low.
6. Build-time rule merging by hash (uBOL mergeRules) and regex validation at build: low-medium; ideas only.
7. GPC header rule + MAIN-world navigator.globalPrivacyControl; optional DNT/X-Client-Data/WebRTC policy (DDG Apache, Ghostery, AdGuard): low.
8. Fingerprint protection and click-to-load from content-scope-scripts: medium-high; Apache-2.0. Also autoconsent heuristic mode (Ghostery): low, MPL.
