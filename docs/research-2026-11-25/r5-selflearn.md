# R5: "Self-learning" AdBrake - evidence and design (2026-11-25)
Labels: CHECKED = I opened the source this session; REPORTED = search summary only; INFERRED = my reasoning.
Not checked: Brave PageGraph/Percival papers in full, Playwright official page (only search snippets), Edge-specific fast-track (none found).

## 0. Bottom line
- Self-improvement is feasible as: server-side pipeline -> human-approved, signed, declarative data file -> existing reviewed extension code applies it.
- Policy risk is NOT mainly "code". Edge says DNR rules "should not be imported remotely unless necessary for functionality" (CHECKED). AdBrake's current weekly EasyList->dynamic-rules update already sits under that sentence. So the honest promise is "no telemetry by default, no remote CODE, rules lists are fetched", not "no remote config".
- LLM/vision at runtime in users' browsers: too slow/unreliable today (AdGuard: vision 10-15 s). Use LLM only offline in CI as a rule drafter.

## 2. How big blockers ship fast under MV3
- Chrome expedited ("skip") review (CHECKED via search snippet of developer.chrome.com/docs/webstore/skip-review): eligible only if declarativeNetRequest is a required permission, only files in rule_resources change, new/changed static rules are "safe" (block, allow, allowAllRequests, upgradeScheme), no rulesets added/removed, nothing else changed; usually live in minutes. This is Chrome Web Store only. Edge equivalent: UNKNOWN (none found). Edge policy 1.2.4: "your extension must be updated only through Partner Center and the Microsoft Edge Add-ons website" unless Microsoft permits (CHECKED).
- AdGuard (CHECKED, https://adguard.com/en/blog/review-issues-in-chrome-web-store.html, updated 4 Feb 2025): Chrome rejected remote download of its Quick Fixes filter as a remote-execution violation; scriptlets flagged "because they could run with parameters"; AdGuard hard-coded scriptlets, applies a rule only if it matches a pre-built category; Quick Fixes removed; plan = Chrome fast-track for DNR "safe rules" every few hours. A later help page (REPORTED) says Quick Fixes returned via dynamic rules, no script execution. Lesson: data that selects among pre-reviewed behaviours passed; data that carries scripts/params to run did not.
- eyeo (REPORTED, gitlab.com/eyeo/adblockplus/abc/webext-ad-filtering-solution/-/issues/432; resources.eyeo.com/mv3-ready): static rules at build time; "a new filter list delivery system" using dynamic rules for between-release updates; custom subscriptions limited by dynamic-rule cap. Chrome 121+: 30,000 safe dynamic rules, 5,000 unsafe (CHECKED via Chrome blog snippet; matches notes).
- uBO Lite (REPORTED, Privacy Guides commit): lists only update with extension releases, historically every 2-7 days via expedited review; only "safe" rules.
- Chrome policy text (CHECKED, https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements): external resources "must not contain any logic"; violation = "execute a string fetched from a remote source"; violation = "Building an interpreter to run complex commands fetched from a remote source, even if those commands are fetched as data"; allowed = "Fetching a remote configuration file for A/B testing or determining enabled features" where "all logic ... is contained within the extension package".
- Edge policy (CHECKED, https://learn.microsoft.com/legal/microsoft-edge/extensions/developer-policies, page dated 2026-07/08):
  - 1.2: "Any `declarativeNetRequest` rules must be clearly declared within the extension, and should not be imported remotely unless necessary for functionality."
  - 1.1.7: "Extensions with obfuscated code aren't allowed. This includes code within your extension package, as well as any external code or resource fetched from the web."
  - 1.2.1: "your extension should not download a remote script and subsequently run that script in a manner that is not consistent with the described functionality."
  - Older Edge MV3 guide (REPORTED, learn.microsoft.com/microsoft-edge/extensions/developer-guide/migrate-your-extension-from-manifest-v2-to-v3): Edge "disallows extensions from using remotely hosted code".
  - Old URL .../store-policies returned 404 today; use the /legal/ URL above.
- What counts as "remote code" for scriptlet parameters (INFERRED from the above): a fixed, in-package scriptlet with parameters taken from a signed list sits in a grey zone (AdGuard was rejected for exactly this). The safe pattern: remote data may only choose from a closed enum of built-in behaviours with typed, bounded fields (CSS selector string, URL pattern, JSON key path) and never contain expressions, regexes executed as code, or function names that map to arbitrary code. CSS selectors and JSON key paths still arguably "logic-light"; keep a schema and length limits. Expect reviewer discretion; UNKNOWN how Edge reviewers treat it.

## 3. Practical pipeline
- Extensions in automation (REPORTED, playwright.dev/docs/chrome-extensions; search snippets): launchPersistentContext with --disable-extensions-except/--load-extension; docs examples use headed; new headless (--headless=new) reported to load extensions; MV3 service worker suspends after ~30 s idle, Playwright keeps the same Worker object. Verify against installed Playwright version (I did not). In CI use xvfb headed Chromium to be safe (INFERRED).
- Measuring "ad shown" (INFERRED, not verified on live YouTube): YouTube - poll the page for .ad-showing class on the player, presence of .ytp-ad-player-overlay, and playerResponse adPlacements; record time from navigation to video.currentTime>0; Twitch - detect the ad banner / the stitched-ad marker and the player-type used. Record screenshot + DOM snapshot for the LLM. Selectors are exactly what breaks; the bot must treat its own detector as versioned too.
- Cost (REPORTED, GitHub pricing pages): public repos on standard hosted runners are free; Linux 2-core ~$0.006/min after the Jan 2026 cut; a nightly 20-minute job on a private repo is ~$3.6/month (INFERRED arithmetic). Check docs.github.com/billing before relying on it.
- Datacenter IP risk (REPORTED, many yt-dlp/forum threads; no official YouTube statement): "Sign in to confirm you're not a bot" appears for datacenter/ASN ranges including GitHub Actions; cookies alone often do not help. Consequences: GitHub-hosted runners may see consent walls/bot checks and different ad behaviour than a real viewer, so the canary result is biased. Options: self-hosted runner on a home/residential connection (small box, free Actions minutes for self-hosted), logged-out only. Do not log in with a real account. Do not use residential-proxy services (INFERRED: ToS and ethics risk, also YouTube ToS forbids automated access; weigh before building). Twitch is likely less hostile but unverified (UNKNOWN).
- Ethics/ToS: running a bot against YouTube/Twitch to watch ads is automated access; low volume (few pages a night) is lower risk but it is the owner's call. Flag, not decide.
- Signing (CHECKED via search of Chrome guide, developer.chrome.com/docs/modern-web-guidance/guides/security/digital-signatures): Ed25519 in WebCrypto is Baseline since 2025-05-29: Chrome 137, Edge 137, Firefox 129, Safari 17. Service-worker availability not verified (SubtleCrypto is exposed in workers per spec; INFERRED). Fallback: ECDSA P-256 for older Edge. Design: public key baked into the extension; file = {version, seq, issued_at, expires_at, min_ext_version, payload_sha256, rules}; verify signature then schema then size limits then rollback check (reject seq <= stored seq unless kill-switch message signed). Private key offline/hardware, not in CI; CI only proposes, a human signs. Same key for kill switch.
- Rollback: keep previous N validated files in chrome.storage.local, apply via updateDynamicRules with remove+add in one call (atomic); a "revoke" file with higher seq that restores the bundled baseline; expiry so a stale or withheld file falls back to bundled rules. Canary rollout: ship to 1% by hashing a random local install id (never sent) against a percentage in the file (INFERRED).

## 4. Privacy-safe feedback
- uBO: no telemetry; "report a problem" is a manual GitHub issue (INFERRED from known practice; not fetched this session - UNKNOWN exact current text). Ghostery: manual broken-page reports via GitHub repo ghostery/broken-page-reports / support form (REPORTED); separate "Human Web" anonymous data collection with a quorum ("only data that a lot of users are sending", hour-based safe set), on by default in most browsers except Firefox (REPORTED, Ghostery policy). AdGuard: UNKNOWN, not found.
- AdBrake feedback design (INFERRED): button "an ad got through" sends nothing until the user confirms a preview. Payload: site (eTLD+1 only, YouTube/Twitch fixed enum), extension version, rule-file seq, a coarse category (video ad / banner / overlay), optional element tag+class names if the user ticks it. No full URL, no video id, no IP stored (use a relay/worker with logging off, or send as a pre-filled GitHub issue / mailto which needs no server). k-anonymity: server publishes a signal only after >= k (e.g. 20) distinct reports for the same (site, category, ext version) in a window; drop below that. Without accounts you cannot dedupe users: abuse (poisoned reports) possible; reports must never auto-change rules, only raise priority for the canary bot and a human.
- Edge disclosures (CHECKED, policy 1.5.1-1.5.3 above): need a privacy policy stating data handling; "may collect ... personal information (including web browsing activity) only if required by and only for use in a prominently disclosed, user-facing feature"; opt-in consent with in-UI opt-out that "immediately and fully stop[s]" collection; data "aggregated and anonymized". Partner Center data-use form and store listing text must be updated before adding the button. Rule-file fetching alone: the fetch reveals IP and extension version to the host (INFERRED) - say so; host on a CDN/GitHub Pages and disclose it.

## 5. Recommended design (phases)
0 (now, no new promise change): Make updater robust. Add schema validation, size caps, rollback to bundled baseline. Reword listing (below). Add Ed25519 verify on the existing weekly list fetch where lists are first-party mirrored (optional).
1 Canary bot (offline, no user impact): self-hosted runner or small PC, logged-out, 5-10 YouTube + Twitch pages nightly; log ad-shown, startup delay, console errors, screenshots. Publishes a private/public report only. Measure bot-detection rate first; stop if >~20% runs are blocked (INFERRED threshold).
2 LLM drafts: LLM sees failed-run DOM/JSON diff and proposes changes limited to the schema (selectors, JSON key paths, URL patterns). Auto-validate: rerun canary, diff against a breakage suite of ~50 non-ad pages (AutoFR-style visual breakage: screenshot diff). Human approves a PR. Expect modest gain; AutoFR parity with EasyList (86% vs 87%) is the realistic benchmark.
3 Signed data file: own domain/GitHub Pages; extension polls (e.g. 6-24 h), verify, apply with the strict schema; Edge listing updated; fall back to bundled. Ship an extension release per schema change (new capability = store review).
4 Opt-in report button with preview and k-threshold as above; reports only prioritise, never auto-publish.
5 Optional: on-device small model / Chrome Prompt API (AdGuard calls local prompt models "most promising" but accuracy short): research only; do not promise.
Kill switch: signed file with seq+revoke that disables remote data and returns to bundled rules; extension can also be paused by shipping a store update (slow).

## 6. Promise wording
Breaks "no remote config": any fetch of a data file from your server (rules/selectors). Current EasyList fetch already breaks a literal "no remote config". Breaks "no telemetry": the report button (even opt-in), any ping with version/ID, and server logs of the poll (IP).
Suggested honest wording: "AdBrake runs no remote code. Its filter lists and a small, signed rules file are downloaded as plain data and checked before use; they can only switch on behaviours already in the extension. Nothing about the pages you visit is sent anywhere. The optional 'report an ad' button sends only what you see in a preview, only after you click Send." Avoid "no remote config" and "no telemetry" if the report button or poll ships; say "no tracking, no analytics, no accounts".
