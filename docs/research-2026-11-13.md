## 1. Causes of freeze and audio desync (ranked)

### C1. Backup playlist numbered differently from the page's playlist, so the player re-downloads a segment it already played (BEST EVIDENCE, CHECKED)
Source: Purple issue #112 maintainer comments, 2026-10-31 (https://github.com/arthurbolsoni/Purple-adblock/issues/112) and finding doc `docs/findings/2026-10-31-same-segment-twice.md` (commit 5630165, https://github.com/arthurbolsoni/Purple-adblock/commit/5630165).
- On TS channels at 9 of 10 midroll starts the player got the segment it had just played again. Backups were numbered by date-time (F-23) and the page's playlist after stitched breaks dates a segment 0.07-1.60 s earlier than the backups'.
- Effect: the player writes that segment's audio OVER itself but appends its video AGAIN. Picture repeats ~2 s and runs 2 s behind the sound, cumulatively: 35.7 s behind after 114 min. Seven loads without Purple stayed within 0.15 s.
- Same mechanism at break END: the page's playlist returns numbered 1-5 (up to 4-6) segments further ahead (their note B-054), so the player fetches the backup's last segments again; picture fell 8-10 s behind the sound at each midroll end (commit 37fe7d8).
- On fMP4 channels the player counts re-fetched segments as new buffer it does not have: the 6.1 s "buffer" is not in the SourceBuffer, the player speeds to 1.03x, latency drifts 8-15 s, and there are 2 s STILLS every ~88 s (finding `2026-10-31-fmp4-stills.md`: 18 stills in 32 min with Purple vs 2 without; the repeated URI at each switch was the `EXT-X-MAP` init segment).

### C2. Old audio left in the MSE buffer after a restart (Firefox, fMP4) (CHECKED)
Finding `2026-11-07-firefox-audio-left-behind.md`, commit 2cffcb1 (F-29).
- IVS frees buffer with short `remove(a,b)` calls from the buffered start. In one SourceBuffer holding both tracks, Firefox removes video up to the next key frame but audio only over the asked range, leaving audio with no video behind the playhead.
- A pause/play (viewer's OR the extension's end-of-break restart) restarts the player timeline at 0 (`timestampOffset` reset); the left-over audio is now AHEAD of the playhead; Firefox reads audio ahead, decodes 52 s+ old audio, then the next append overwrites it. User symptom (#112): "audio skipping between present and past". 4-37 old-audio ranges after each of 18 restarts; the same happened without Purple after plain pause/play (9 restarts), so it is partly a player/Firefox bug that restarts amplify.
- Matches TTV-AB #37 (2026-06-25): "audio from 5+ minutes ago plays for 1-2 s, random cutting back", pause/resume changes what is heard, only reload fixes. TTV-AB's own diagnosis then: "a stale Twitch media element could get unmuted after ad recovery and mix old audio back in" (v10.0.0). User still reported it on v12.0.0 (2026-07-14). ryanbr #264 (2026-10-19) "an outdated audio started playing and looping".

### C3. Switching between streams with different timelines leaves holes or jumps in the buffer (CHECKED, TTV-AB/vaft changelogs)
- Native <-> backup swap leaves the playhead with nothing buffered across a gap: ryanbr #244 (2026-06-17) logs `<video> 350-380 then 398-404 (18 s gap)` on a 360p autoplay backup, "loading circle mid-break".
- TTV-AB changelog (https://github.com/GosuDRM/TTV-AB/blob/main/CHANGELOG.md): "Prevent playback from freezing when clean backup sessions use different segment numbers, including low-to-high switches" (~v22-24); "Keep segment numbering continuous when switching from temporary holds to clean streams ... to avoid freezes from large sequence jumps"; "Keep clean segments when stream timestamps overlap by up to 50 ms"; "Repeat at most half a second of already watched video when switching" (26.0.2).
- Quality mismatch: backups often only 360p ("autoplay" type) -> resolution/SPS change inside one MSE buffer; TTV-AB #75, ryanbr 'Stuck at 360p'; 1440p HEVC/AV1 variants cannot be decoded in the ad break -> black screen/error 3000/4000 (vaft 68.5.0 AV1 fix, TTV-AB #47).
- Purple note B-059: "same decode times for a live segment on every token and rendition" (finding doc `2026-11-06-fmp4-breaks-on-2.7.1.md`), i.e. timelines of live segments ARE aligned across tokens, so the mismatch is in MEDIA SEQUENCE NUMBERS and the page's own blanking/merging, not decode time.

### C4. Stripping or blanking ad segments (CHECKED in vaft source)
- Stripping leaves an empty/short playlist; "loading wheel while stripping" and black-screen "Blocking Ads (Stripping)" (pixeltris #481, #506). vaft keeps `RecoverySegments` and a blank MP4 for ad segment fetches; BLANK_MP4/recovery injection leaves "timestamp weirdness ... causing audio/video desync over time", which is WHY vaft hard-reloads after a strip break (comment in ryanbr vaft.user.js near line 1840, quote: "soft reload preserves the existing MediaSource buffer, and any timestamp weirdness from strip/BLANK_MP4/recovery injection persists across it").

### C5. Buffer-monitor "fix" itself causes freezes, and hidden tabs (CHECKED)
- vaft pause/play fix on a thin live-edge buffer "interacts badly with Twitch's playback-monitor (snaps to buffered region 0.04xxx), creating a self-sustaining cascade" (ryanbr vaft.user.js line 122 comment, DangerZone lowered 1 -> 0.5, #208). pixeltris #492: endless buffering after v20; `position > 5` condition in monitor (never solved).
- Background tabs: browsers stop drawing video; stream "freezes with no sound when tabbed out, plays minute-old audio on return" (ryanbr #263, v68.5.7, 2026-10-07 closed). TTV-AB "Stop the check for frozen video after an ad break from pausing/reloading the stream while the tab is hidden".
- "Audio running, video frozen" wedge after break: playhead advances but `getVideoPlaybackQuality().totalVideoFrames` flat (vaft 68.5.0 / TTV-AB 12.0.0).
- Player left PAUSED after switch: Purple T-828 / commit notes: page pause via MPRIS media controls at a break left the player paused with nothing resuming (finding `2026-10-31-page-pause-mpris.md`, referenced in fmp4-stills doc). Directly matches "needs manual click on play".

### Not found
- Missing EXT-X-DISCONTINUITY as a cause: no source I opened blames it. UNKNOWN. (vaft source mentions "discontinuity" only in a comment about MSE re-init pop, line ~2670.) Purple's cause is sequence numbers, not discontinuity tags.
- Audio-only renditions as a cause: not found. UNKNOWN.

## 4. Recommendations for Twitch Ad Shield (ranked by likely impact)
1. Number backup/ad-stripped playlists by `EXT-X-TWITCH-LIVE-SEQUENCE` (and keep `EXT-X-MEDIA-SEQUENCE` consistent with the page's) so the player never asks for a segment it already played. This is the proven root cause of cumulative desync (Purple F-27). Mismatch is most likely at switch-in and switch-back.
2. Add a "repeat detector" (F-28): at each new playlist compare the live number listed after the player's last-fetched segment with its newest; if it is not newer, do ONE pause/play restart. Must also run when the page's playlist was blanked/merged (T-832).
3. Widen SourceBuffer.remove for combined audio+video SourceBuffers (F-29) in the MAIN world; cheap and mostly fixes Firefox audio-from-the-past. Chrome impact UNKNOWN (measured on Firefox and Brave; the Brave measurements showed no issue with removals).
4. Post-break health watchdog: frozen `currentTime` for 3 ticks with `readyState<3` and a buffered gap -> seek to gap start+0.05; frame-count wedge detector -> nudge then reload; explicit "player left paused after switch -> play()" when `video.paused` and not user-initiated. This covers the "needs manual click on play" symptom. Guard: only when tab visible, cooldown 15 s, max 2 per break.
5. Prefer soft path: do not hard-reload when nothing was stripped or when the backup quality equals native (TTV-AB 26.0.3); never switch to a backup lower than the codec of the stream (HEVC/AV1 -> AVC variant swap per vaft); keep 360p autoplay as last resort.
Do-not: do not run a pause/play buffer fixer on a live-edge buffer < 1 s without both conditions (frozen AND draining); this self-triggers.

## 5. General ad / tracker / cookie blocking in MV3

### 5.1 DNR limits (CHECKED, Chrome docs https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest, 2026-11-13)
- `GUARANTEED_MINIMUM_STATIC_RULES` 30,000 (shared by all enabled static rulesets); up to 100 static rulesets, 50 enabled at a time; dynamic rules 30,000 (safe) + unsafe max 5,000; session rules 5,000; regex rules 1,000 per type, each < 2 KB compiled; max 5,000 disabled static rules. The global pool above the guarantee is 330,000 per the uBOL FAQ (CHECKED, https://github.com/uBlockOrigin/uBOL-home/wiki/Frequently-asked-questions-(FAQ)); the Chrome page itself gave no number. Rules beyond the global pool are not enforced. Static rules persist across sessions but are re-read from `rule_resources` on update.
- Consequence: rulesets must be built into the package; no remote list updates (store review). Extension updates are the update channel (AdGuard auto-builds on a CI schedule).

### 5.2 Conversion tools
- uBO Lite (https://github.com/gorhill/uBlock/tree/master/platform/mv3, GPL-3.0): `make mv3-chromium` downloads lists and runs a Node script (`tools/make-mv3.sh`) that compiles them to rulesets in `rulesets/`; no network at runtime. Not supported: dynamic filtering, per-site switches, CNAME uncloaking, `replace=`, regex `removeparam`, many regex filters, element picker. Generic cosmetic off unless "Complete" mode. (CHECKED README + FAQ.) Version 2026-06 added custom filters and external list subscriptions (REPORTED in FAQ text).
- AdGuard (https://github.com/AdguardTeam/tsurlfilter, GPL-3.0): npm `@adguard/dnr-converter` (filter list -> DNR; has source maps, CSP conversion), `@adguard/dnr-rulesets` (ready AdGuard rulesets, CLI `dnr-rulesets load`, manifest patcher), `@adguard/agtree` parser, `@adguard/tswebextension` (cosmetic/scriptlet engine). AdGuard MV3 extension: rulesets from `filters.adtidy.org/extension/chromium-mv3/filters.json`, JS "local script rules" shipped in the package (CHECKED READMEs).
- Ghostery (https://github.com/ghostery/adblocker MPL-2.0; extension GPL-3.0): engine library with cosmetic filters and DNR support (repo README grep only; details UNKNOWN, not opened).
- Cosmetic filtering in MV3: ship content scripts and CSS statically (uBOL cannot inject strings with `scripting.registerContentScripts`); CSS via `insertCSS` per-site from precompiled data; scriptlets must be bundled (matches why AdGuard ships local script rules).

### 5.4 Complaints / wishes we can improve on (mostly REPORTED, forum/mirror snippets from web search 2026-11-13; Reddit itself unreachable)
- uBOL lacks: dynamic filtering, per-site switches, element picker, CNAME uncloaking, generic cosmetic by default (FAQ CHECKED, plus mirrored r/uBlockOrigin 2025-07 thread REPORTED).
- Users complain Lite cosmetic filtering is weaker than full uBO; ideas: ship a simple, visible per-site "pause" and an element-hiding picker that stores selectors as dynamic DNR/CSS rules; show a per-page blocked count (needs `declarativeNetRequestFeedback`).
- Cookie banners: users wish for "reject all" rather than hide, with the ability to report unsolved sites (Consent-O-Matic has a report list; autoconsent is heuristic + rules).
