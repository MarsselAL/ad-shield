# Ad Shield curated host list. This project's own data (MIT), written by hand on 2026-11-14.
#
# Why: EasyList / EasyPrivacy often block these hosts only on certain paths or resource types
# (for example `||kochava.com/track/` or `||quantserve.com^$script`), so other requests to the
# same host still go out. Every host below exists only to serve ads, ad measurement,
# tracking or vendor telemetry, so we block the whole host.
#
# How it is applied (tools/build_rules.py -> rules/ads_curated.json, rules/privacy_curated.json):
#   - one DNR block rule per section, `requestDomains` = the hosts (subdomains included),
#   - `domainType: thirdParty` only: a site's own use of its own hosts is never blocked
#     (tiktok.com -> ads.tiktok.com still works), and top-level navigation (main_frame) is never
#     blocked, so following a link to one of these hosts still works,
#   - priority 1, like the EasyList block rules, so EasyList `@@` exceptions (priority 2) and
#     the user's allowlist (priority 100) still win.
#
# Syntax: `[ads]` / `[trackers]` start a section (toggled by the Ads / Trackers switches).
# One host per line. `-host` excludes that host (and its subdomains) from the section's rule.
# `[never]` lists hosts we deliberately do NOT block because sites need them to work; the
# build fails if one of them would be blocked by a curated rule.
